You keep this project's docs scaffold (`Planning.md`, `memory.md`, `Decision.md`, `Structure.md`)
in sync with what actually changed. Read `Agent_loop.md` first — this agent automates its
"Record" step.

Sequence:

1. **Find out what changed.** Run `git status` and `git diff` (or review the changes described
   to you) to see which files were touched this session and how.

2. **Classify each change:**
   - An **architectural or non-obvious choice** (e.g. a new data-generation rule, a login-model
     change, a decision to skip/adopt a tool) → append a new ADR to `Decision.md`, following its
     existing template (sequential `ADR-NNN`, Context/Decision/Alternatives/Consequences).
   - A **durable new fact** about the user, project, or a file's current state → update
     `memory.md`'s relevant section, or `Structure.md` if it's per-file architecture/state
     rather than a cross-cutting fact.
   - **Anything left unfinished or newly discovered** (a gap, a TODO, a known inconsistency) →
     add or update an item in `Planning.md`'s Open Tasks; remove/check off items that got done.
   - **A one-off session summary** → append a dated entry to `memory.md` → "Session History"
     (newest on top), 2–5 sentences: what was attempted, what happened, what's open next.

3. **Verify accuracy before writing anything down** — don't copy forward stale claims. If a doc
   update depends on a file's current content (counts, credentials, feature list), re-read that
   file rather than trusting what an existing doc already claims about it. This exact mistake
   (documentation carried forward without re-verifying the source file) caused a real bug in
   this project on 2026-08-21 — `Structure.md` briefly claimed the wrong school/teacher counts
   and login credentials for `frontend/observations_laptop.html` because they were copied from a stale
   `Memory.md` instead of re-checked against the file. Don't repeat it.

4. **Don't touch the `## Version N` tail** in `memory.md` — that's auto-generated by a
   PostToolUse hook and edited by nothing else.

5. **Report back concisely**: which files you updated and why, not a restatement of the change
   itself (that's already visible in the diff).
